## 1. 目标和范围

### 做什么

一个 macOS 原生应用，让人不用终端、不碰 YAML，就能装好鼠须管（Squirrel / Rime）、选输入方案、调外观，并且能把整套配置一键导出、在新电脑上一键还原。

- 现在只有作者自己用，以后公开发布。
- 一台电脑只有一套配置。**不做 Profile**（多套配置切换）。

### 第一版范围

| # | 功能 | 说明 |
|---|---|---|
| 1 | 安装和环境检查（F1） | 检测、一键安装鼠须管，引导添加输入法并自动检测 |
| 2 | 方案目录（F2） | 雾凇全拼、雾凇小鹤双拼、极点五笔 86（含拼音混输）：安装、更新、卸载、启用、排序 |
| 3 | 外观（F4） | 配色（浅色、深色）、候选字/序号/注释字号、横排竖排、每页候选数 |
| 4 | 一键导入导出 | 见第 5、6 节 |
| 5 | 接管已有配置 | 第一次打开时认出现有 `~/Library/Rime`，见第 6.2 节 |
| 6 | macOS 文本替换导入（F6） | 读系统数据库，生成自定义短语，有变化时提示同步 |
| 7 | 备份、校验、部署、还原（F8） | 见第 6.1 节和第 7 节 |

### 第二版再做

F3 个人词库编辑器、F5 按键设置、F9 试打预览、iCloud 多台电脑同步、在线方案清单。

### 不做

Windows（小狼毫）、直接编辑 YAML 的高级模式、App Store 版本。

### 运行环境

- 最低 **macOS 27**。
- Swift 6.4、Xcode 27（宿主机已有）。
- 应用运行时**不依赖** python3、git、Homebrew（新 Mac 上都没有或是空壳）。

## 2. 哪些要用户亲手做

| 事项 | 原因 |
|---|---|
| 安装鼠须管时输一次管理员密码 | 要写入 `/Library/Input Methods`，应用弹系统授权框 |
| 在系统设置里添加一次鼠须管 | 实测程序无法启用本体，注销也没用；应用打开设置页、给图文说明、自动检测 |

除此之外的一切（下载、校验、安装、生成配置、部署、导入导出）由应用自动完成。不需要注销。

## 3. 整体结构

```
┌──────────────────────┐    ┌──────────────────────┐
│ 应用（SwiftUI 界面） │    │ rimectl（命令行）    │
└──────────┬───────────┘    └──────────┬───────────┘
           └────────────┬───────────────┘
                        ▼
              RimeKit（核心库，全部逻辑）
                        │
     ┌──────────────────┼────────────────────┐
     ▼                  ▼                    ▼
 鼠须管自带的工具     ~/Library/Rime     ~/Library/Application Support/
 rime_deployer                           squirrel-macos/
 rime_dict_manager
```

三个构建目标：

| 目标 | 内容 |
|---|---|
| `RimeKit` | Swift Package 里的库。**所有逻辑都在这里**，不含界面代码 |
| 应用 | SwiftUI 界面，只调用 RimeKit |
| `rimectl` | 命令行工具，也只调用 RimeKit。用于在测试机里通过 SSH 跑完整流程；以后可以打包进应用给高级用户用 |

### RimeKit 的模块

| 模块 | 职责 |
|---|---|
| `Environment` | 找到鼠须管、读版本；用 TIS 接口查询和切换输入法；打开系统设置键盘页 |
| `Installer` | 下载鼠须管 pkg；校验签名（团队 ID `28HU5A7B46`）和公证；安装 |
| `Catalog` | 读内置的 `catalog.json` |
| `PackageStore` | 下载上游 zip、解压、按版本缓存、检查结构 |
| `Settings` | 用户的所有选择，读写 `settings.json` |
| `ConfigGenerator` | 设置 + 上游文件 + 个人内容 → 暂存区里一份完整的 Rime 用户目录 |
| `Deployer` | 校验暂存区 → 备份 → 写入 → 通知鼠须管 → 检查结果 |
| `Ledger` | 记录应用写进 `~/Library/Rime` 的文件和哈希，发现外部改动 |
| `Takeover` | 第一次打开时识别已有配置 |
| `Transfer` | 导出、导入 |
| `UserDB` | 包装 `rime_dict_manager`，导出、合并输入习惯快照 |
| `TextReplacement` | 读 `TextReplacements.db`（用系统自带的 SQLite 库），生成短语 |

### 两个技术细节

- **管理员权限**：`Installer` 接受一个「怎么提权」的参数。应用用系统授权弹窗（`osascript` 子进程执行 `do shell script … with administrator privileges`，不在主线程里跑，不卡界面；阶段 8a 定下）；`rimectl` 在测试机里用 `sudo`（测试机已配好免密 sudo）。第一版不做 `SMAppService` 特权辅助程序。安装前三道检查：sha256 等于 GitHub 接口的 `digest`、`pkgutil` 确认签名和公证且团队 ID 是 `28HU5A7B46`、`spctl` 通过（只靠 `spctl` 不够，改过的包它也放行，已实测）。提权以后还要再核对一次：先把安装包复制到只有 root 能写的临时目录，在副本上重新查 sha256、签名公证和团队 ID，再安装这份副本（防止检查完到输密码这段时间里，同一用户的其它程序把暂存目录里的包换掉）。已经装了同版本或更新版本就不重装。
- **解压**：用系统自带的 `/usr/bin/ditto -x -k`（已验证：干净的 macOS 27 上可用）。各包的目录结构见 [upstream-layouts.md](../../upstream-layouts.md)，路径一律用查找定位，不写死（极点五笔的 zip 带顶层目录 `rime-wubi86-jidian-master/`，雾凇 `full.zip` 没有顶层目录）。

### 第三方代码依赖

只有 **Yams**（YAML 读写，MIT 许可证），打包进应用。

## 4. 方案清单 `catalog.json`

一个独立的 JSON 文件，打包进应用，不写死在代码里。格式按「以后可以放到网上」设计：以后可以加一层「先拉在线版，失败用内置」，现在不做。

每个包写明：

| 字段 | 内容 |
|---|---|
| `id`、名字、类别、简介、许可证、主页 | 展示用 |
| 下载来源 | GitHub 仓库 zip（`codeload.github.com`，版本用提交号）或 Release 附件（版本用附件更新时间） |
| 安装文件 | zip 里哪些文件放进 Rime 目录，放到哪里 |
| 必须存在的文件 | 解压后检查，缺了就说明上游结构变了 |
| 方案 | 包里有哪些方案（schema id、显示名） |
| 依赖 | 依赖哪些别的包 |
| 选项 | 用户能选的项，每个选择对应要生成的文件和要加的补丁 |
| 上游自带的 `*.custom.yaml` | 当作默认值读入，**不直接复制**（避免覆盖用户设置） |
| 自定义短语 | 这个方案自带短语功能，还是要由应用注入 `table_translator@custom_phrase` |
| 上游自带、会和应用生成文件同名的文件 | 例如雾凇 `full.zip` 自带 `custom_phrase.txt`（还有会覆盖鼠须管默认值的 `default.yaml`、`squirrel.yaml`）。应用生成同名文件时，要把上游的内容当默认值合并进来，不能直接覆盖丢掉。具体规则在阶段 2 定 |
| 字号写在哪里 | 全局 `style`，还是每个配色方案里面（极点五笔是后者） |
| 个人词库模板 | 上游自带、用户会往里加词的词库（极点五笔的 `wubi86_jidian_user.dict.yaml`、`wubi86_jidian_user_hamster.dict.yaml`）。接管已有配置时，和上游不一样的就收进 `personal/` |

第一版的包：

| 包 | 来源 | 方案 | 说明 |
|---|---|---|---|
| `rime-ice` | `iDvel/rime-ice` | `rime_ice`（全拼）、`double_pinyin_flypy`（小鹤双拼） | GPL-3.0，运行时下载，不打包 |
| `rime-ice-dicts` | `iDvel/rime-ice` 的 `cn_dicts` | 无（只有词库） | 给别的包当拼音词库用 |
| `wubi86-jidian` | `KyleBing/rime-wubi86-jidian` | 五笔、拼音混输、简入繁出等 | Apache-2.0。选项「拼音词库」：自带 `pinyin_simp`，或雾凇（依赖 `rime-ice-dicts`，生成 `pinyin_ext` 总词库和对应补丁，做法同 [reference-wubi-profile.md](../../reference-wubi-profile.md)） |

具体用 Release 附件还是仓库 zip、装哪些文件，在实现计划里逐个包核对后写定。

## 5. 数据和文件

### 应用自己的数据

```
~/Library/Application Support/squirrel-macos/
├── settings.json      # 用户的所有选择
├── personal/          # 个人内容的正本：个人词库、手动短语
├── ledger.json        # 应用写进 ~/Library/Rime 的文件和哈希
├── packages/          # 上游包缓存，按「包名@版本」存放
├── staging/           # 生成和校验用的暂存区
├── backups/           # 每次写入前对 ~/Library/Rime 的备份
└── lock               # 防止应用和 rimectl 同时改
```

**个人内容的正本在 `personal/`**，生成配置时复制进 `~/Library/Rime`。这样上游更新不会覆盖它们（极点五笔更新时会用空模板覆盖 `wubi86_jidian_user.dict.yaml`）。

### `settings.json`

| 部分 | 内容 |
|---|---|
| 格式版本号 | 以后改格式时兼容旧文件 |
| 方案 | 启用的包；每个包启用哪些方案；全部方案的顺序（第一个是默认方案） |
| 包选项 | 例如极点五笔「拼音词库 = 雾凇」 |
| 外观 | 浅色配色、深色配色；候选字、序号、注释字号；横排或竖排；每页候选数。字号浅色深色一起改 |
| 文本替换 | 是否同步；上次同步时的整体哈希和每一条的哈希（只存哈希，用来数有几条变化；导出时去掉） |
| 保留的补丁 | 接管时认不出的 `.custom.yaml` 补丁项，按文件存，生成时原样写回 |

外观只用真正生效的键名：`font_point`、`label_font_point`、`comment_font_point`。**不用 `candidate_font_point`**（无效）。

### `ledger.json`

每个由应用写入 `~/Library/Rime` 的文件：相对路径、SHA-256、写入时间。下次写入前，用它判断文件有没有被外部改过、哪些旧文件该删掉。

### `~/Library/Rime` 里的文件分三类

| 类别 | 例子 | 应用怎么对待 |
|---|---|---|
| 应用管理的 | 上游方案文件、生成的 `*.custom.yaml`、总词库、个人词库、`custom_phrase.txt` | 生成、覆盖、删除，都记进 ledger |
| Rime 自己的 | `build/`、`installation.yaml`、`user.yaml`、`*.userdb` | 不写（输入习惯只通过 `rime_dict_manager` 合并） |
| 不认识的 | 用户自己放的其它文件 | 永远不动，界面上列出来 |

### 导出文件

一个 zip 包。扩展名等应用名定了再定（见第 11 节）。

```
manifest.json     # 格式版本、导出时间、settings、导出时的上游版本、各部分条数
personal/
  dicts/          # 个人词库 *.dict.yaml
  phrases.txt     # 手动短语
userdb/           # 输入习惯快照 <词典名>.userdb.txt（rime_dict_manager --export，可选，默认带上）
```

- 不放任何上游方案文件。导入时**总是下载最新版**；manifest 里的版本只用来参考和排查问题。
- 从文本替换生成的短语**默认不导出**（隐私；同一个 Apple 账户在新电脑上会自动同步，导入时重新生成）。
- 导出时可以取消勾选「包含输入习惯」。

### 作者现有五笔配置的对应关系（接管的第一个测试样本）

| 现有配置 | 在应用里 |
|---|---|
| 极点五笔 6 个方案，拼音混输排第一 | 方案列表和顺序 |
| `pinyin_ext` 总词库（雾凇 8105 + base + ext） | 极点五笔选项「拼音词库 = 雾凇」，总词库和 5 个补丁由应用生成 |
| 5 个补丁里的 `custom_phrase` 段落 | 应用生成：有短语就注入 |
| 字号 24/20/20，`roseo_maple` / `roseo_maple_dark` | 外观设置 |
| `-` `=` 翻页（`key_binder/bindings`） | 保留的补丁 |
| `wubi86_jidian_user.dict.yaml`、`pinyin_user.dict.yaml` | `personal/` |
| `custom_phrase.txt` | 拆成两部分：和当前文本替换对得上的条目算「文本替换生成」，其余算「手动短语」 |

### 5.1 生成规则

阶段 2 定下，经过 `rime_deployer` 编译和模拟打字验证（自造方案 + 真实的雾凇、极点五笔）。

1. **要用到的包** = 启用的方案所属的包 + 这些包所选选项的依赖（再按清单的依赖顺序展开）。
2. **复制上游文件**：按安装顺序复制每个包缓存里的文件，**不复制**根目录的 `*.custom.yaml`（当作上游默认补丁）和 `LICENSE`。两个包有同一路径的文件时后面的覆盖前面的；内容不同就记一条提醒。
3. **补丁按顺序叠加**（Rime 按顺序应用补丁，后面的覆盖前面的，已实测）：上游自带的 `<名字>.custom.yaml` → 包选项的补丁 → 短语注入 → 设置里保留的补丁 → 应用管理的键。同一个键再写一次时，删掉旧的、放到最后。
4. **应用管理的键**：`default.custom.yaml` 写 `schema_list`（设置里的顺序，第一个是默认方案）和 `menu/page_size`；`squirrel.custom.yaml` 写外观。外观里的字号、横竖排同时写到 `style/<键>` 和**实际生效的浅色、深色配色**的 `preset_color_schemes/<配色>/<键>`（极点五笔把字号写在配色里，只改 `style` 不生效）。实际生效的配色：设置里指定的 > 补丁里写的 > 包里的 `squirrel.yaml` 写的。
5. **包选项**：所选选项的补丁写进对应方案的 `<方案>.custom.yaml`，**选项里列出的方案都写，不管启用没启用**（启用的方案会通过 `schema/dependencies` 用到没启用的方案：极点五笔的混输靠 `pinyin_simp` 的翻译器指向 `pinyin_ext`，Rime 才会编译这个总词库；Rime 不会因为 `reverse_lookup/dictionary` 去编译词库，已实测）；选项要生成的总词库（如 `pinyin_ext.dict.yaml`）由应用生成，标了「只在有个人词库时」的导入表，只在用户有同名个人词库时才挂上。
6. **个人词库**：`personal/dicts/*.dict.yaml` 复制到输出目录根，和上游同名时**用个人的**。
7. **短语**（手动短语 + 文本替换生成的短语，有短语时才处理）：对每个启用的方案，如果方案本来就有 `table_translator@custom_phrase`，用它的 `custom_phrase/user_dict` 指定的文件（雾凇全拼是 `custom_phrase.txt`，小鹤双拼是 `custom_phrase_double.txt`）；没有的（极点五笔）注入短语翻译器，用 `custom_phrase.txt`。每个短语文件 = 上游同名文件原样（如果有）+ 用户的短语；上游没有就新建。
8. 只有内容不为空的补丁才生成 `.custom.yaml` 文件。

### 5.2 接管识别规则

阶段 5 定下，用自造包、真实上游的脱敏样本和测试机验证。

1. **有没有配置**：Rime 目录里有配置文件（不算 `build/`、`user.yaml` 这些 Rime 自己的运行文件）。
2. **方案**：`default.custom.yaml` 补丁里的 `schema_list`，没有就看 `default.yaml`。清单里没有的方案不启用，文件原样保留，告诉用户。
3. **对照的默认补丁** = 包里自带的 `<名字>.custom.yaml` + 认出的选项的补丁。只看 `default`、`squirrel`、这些包的方案和自带补丁对应的 `.custom.yaml`，别的（如 `weasel.custom.yaml`）原样保留。
4. **选项**：某个选择的补丁全都在、要生成的总词库也在，就算选了它；都对得上时选条件最多的。只对上一部分时提示。
5. **用户补丁逐项比**：拆成叶子（`menu: {page_size: 5}` → `menu/page_size`）和默认补丁比。应用管理的键变成设置；和默认一样的丢掉；不一样的存成「保留的补丁」；和默认补丁、应用管理的键都没关系的项整项原样保留。默认补丁有、用户补丁没有的项，提示「接管后会按上游默认加上」。键里有 `/` 的映射（标点映射）整个当一项。
6. **外观**：看实际生效的值（配色里的优先于全局 `style`），和不接管时的默认值比，不一样才写进设置。浅色深色不一样时用浅色的并提示。
7. **个人词库**：清单里标出的个人词库模板和上游不一样的；所选选项总词库里「只在有个人词库时」导入的词库。
8. **短语**：启用的方案用到的短语文件，去掉上游自带的；和 macOS 文本替换一样的算文本替换（打开同步），其余算手动短语。
9. **预览和确认**：在暂存区按识别结果生成一遍，逐个文件比，列出会换掉、不变、新加、原样保留的文件。用户确认后走 6.1（覆盖前完整备份，这份永久保留）；写入成功后才保存设置和个人内容。已经由应用管理的目录不再接管。

## 6. 主要流程

### 6.1 应用改动（所有改动都走这一条路）

1. 缺的上游包先下载（自动带上依赖），检查结构。
2. 在 `staging/` 生成完整的 Rime 目录：现有目录里「不认识的」文件 + 应用生成的文件。
3. 用 `rime_deployer --build` 编译暂存区：退出码 0 **并且**没有 `E` 开头的日志行才算成功（补丁写坏时退出码也是 0，已实测）。**失败就停**，真实配置没动。
4. 对照 ledger：应用管理的文件在应用外被改过、删了，或者这次要覆盖应用不管的文件，都列出来问用户（覆盖前先备份；被改过的个人词库可以采用外部的修改，见第 7 节）。
5. 备份 `~/Library/Rime`。
6. 写入：只写应用管理的文件，删掉 ledger 里有、这次不再需要的文件，别的不碰。
7. 通知鼠须管：在运行就 `Squirrel --reload`，没运行就 `open` 启动它（实测没运行时 `--reload` 没反应）。
8. 检查结果：`user.yaml` 的 `var/last_build_time` 变了就算部署完（最多等 120 秒），再看这次新增的 ERROR 日志（`$TMPDIR/rime.squirrel/`）。不看 `build/` 文件的修改时间（只改外观时方案不重编译），也不能只靠 INFO 日志的 “finished” 那一行（有缓冲）。
9. 更新 ledger。

### 6.2 第一次打开

1. **环境检查**：鼠须管装了没有 → 没装就一键安装 → 本体 `im.rime.inputmethod.Squirrel` 启用了没有（用 TIS 的 `kTISPropertyInputSourceIsEnabled` 判断，不读偏好文件）→ 没有就打开系统设置键盘页，配图文说明，每秒检测一次，好了自动切换过去。切换后**主动 `open` 启动鼠须管**（实测：切换后鼠须管不会自己马上启动，`~/Library/Rime` 也不会生成）。等待用户添加时每秒查一次，等待期间让 run loop 转起来（同一个进程里才能看到变化），TIS 的调用都在主线程上做（否则会崩溃）；最多等 10 分钟，超时就提示用户添加好后再点一次。（阶段 4 实测）
2. 看 `~/Library/Rime`：
   - **已有配置**：完整备份（这份永久保留）→ 下载能认出的上游包做对照 → 识别方案、包选项、外观、个人词库、短语、补丁 → 把识别结果给用户看，**用户确认后**走 6.1。认不出的文件列出来，原样保留。第一版只认清单里的包。识别规则见 5.2；命令行是 `rimectl takeover`（预览）、`rimectl takeover --confirm`。
   - **空的**：选一个起步方案（雾凇全拼、雾凇小鹤双拼、五笔 + 拼音混输），走 6.1。
   - **用户有导出文件**：走 6.4。

### 6.3 导出

把 settings、`personal/`、输入习惯快照（`rime_dict_manager` 导出，可选）打成一个文件，用系统「存储」对话框选位置。

导出输入习惯前要先退出鼠须管（实测：鼠须管打开着数据库时导不出来），导完马上 `open` 启动它。界面上提示「正在导出，输入法会暂停几秒」。

退出后如果用户正好在打字，系统可能马上又把鼠须管拉起来、重新锁住数据库。所以要看 `rime_dict_manager` 的退出码：失败就再退出一次鼠须管重试；重试几次还不行，就报错，说明「请先别打字，再点一次」。导入时的合并也一样。

做法（阶段 6 定下）：zip 用系统自带的 `ditto -c -k --norsrc --noextattr --noqtn` 打包（不会多出 `__MACOSX/`）。输入习惯用 `rime_dict_manager --export`，在 Rime 目录里运行；被占着就再退出一次鼠须管重试，最多 3 次；鼠须管原来在运行的，导完再启动。命令行是 `rimectl export 文件 [--no-userdb]`。

### 6.4 导入

1. 用户选择导出文件，检查格式版本号。
2. 鼠须管没装就装。
3. 引导添加输入法；**同时**在后台下载最新上游包。
4. 还原 settings 和 `personal/`。
5. 走 6.1。
6. 合并输入习惯快照：先退出鼠须管（`killall Squirrel`），用 `rime_dict_manager --import` 合并（实测是合并，不是覆盖），再 `open` 启动它。
7. 文本替换同步开着的话，重新生成短语，再走一次 6.1。

导入时如果 `~/Library/Rime` 里已有配置，先完整备份再导入：应用还没管过 Rime 目录时这份永久保留；已经由应用管理时是普通备份，跟着最近 10 份轮换（修复 0.1.1 定下）。

做法（阶段 6 定下）：
- 导出文件当作不可信数据：只认 `manifest.json`、`personal/dicts/*.dict.yaml`、`personal/phrases.txt`、`userdb/<名字>.userdb.txt` 这些普通文件，别的跳过并提示。
- 应用里原来有设置时，先把原来的设置和个人内容另存成 `before-import/<时间>.zip`（Rime 目录的备份不含这些）。
- 写入时覆盖应用外的改动和同名文件；这次的备份说明「导入前」（永久保留与否同上；另存的「导入前」设置文件只留最近 10 个）；写好后、通知鼠须管前保存设置和个人内容。
- 输入习惯合并不上时，配置照样导入完成，提示再导入一次（配置不会重复写，输入习惯是合并）。
- 命令行 `rimectl import 文件` 要求先装好鼠须管（`rimectl install`、`rimectl activate`）；应用里把这几步串成一键（阶段 8）。

### 6.5 文本替换同步

应用启动时和用户点「检查」时（第一版应用不常驻后台，所以只在应用打开时检查）：读数据库 → 用 [verified-facts.md](../../verified-facts.md) 第 5 节的规则过滤（快捷码只有字母，内容不含换行和 Tab）→ 算哈希和上次比 → 有变化就提示「有 N 条变化，要同步吗」→ 用户同意后重新生成 `custom_phrase.txt`（手动短语 + 文本替换 + 上游方案自带的默认短语，合并规则见第 4 节，阶段 2 定），走 6.1。

做法（阶段 7 定下）：
- 读的时候把用不了的条目数出来：快捷码里有英文字母以外的字符（Rime 里打不出来）；内容是空的、有换行或 Tab、以 `#` 开头。只显示条数。
- 只有数据库文件确实不存在才当作没有文本替换；没权限等「看不见」的情况报错，不悄悄去掉已经同步的短语。
- 记录：每一条按「短语<Tab>编码」算 SHA-256，排好序存进设置；和现在的比，数出新增、删掉几条（改了内容算一删一增）。导出文件和 `rimectl settings show` 里都不放这份记录。
- 同步开着时，任何一次写入（应用改动、接管、导入）都带上当前的文本替换，并更新记录；关掉同步会去掉文本替换生成的短语，手动短语不受影响。还原备份后清掉记录，提示重新同步。
- 命令行：`rimectl textreplacement status | sync | off`（`sync`、`off` 也认 `--overwrite`、`--adopt-personal`）；`rimectl doctor` 在同步开着时多一项「文本替换」。应用界面的「检查」「同步」按钮和开关在阶段 8。

## 7. 出错处理

**总原则：真实配置只在 6.1 的第 6 步才改。** 之前任何一步出错，`~/Library/Rime` 完全不动。

| 情况 | 处理 |
|---|---|
| 下载失败 | 自动重试几次；本地有旧版本缓存就问要不要先用旧版；导入流程停在这一步，可以点「重试」接着来 |
| 上游结构变了（缺清单里的必需文件） | 停下，提示「上游方案目录结构变了，需要更新应用」 |
| 鼠须管安装包签名不对或没公证 | 拒绝安装 |
| 暂存区编译失败 | 真实配置没动；显示翻译后的错误，可展开原始日志 |
| 外部改动 | 列出文件，用户选：覆盖（先备份）或放弃这次改动。被改的是个人词库时，多一个「采用外部的修改」（拷回 `personal/`） |
| 写入到一半失败 | 自动用刚才的备份还原，再报告 |
| 部署后检查不通过 | 提示问题，可一键还原到上一个备份 |
| 文本替换数据库读不了 | 实测未签名、不开沙盒的独立应用不用授权就能读，所以正常情况下不会遇到。万一读不了（例如以后正式签名或开沙盒后行为变了），显示原因，并说明可以去「隐私与安全性」检查权限 |
| 应用和 `rimectl` 同时改 | 锁文件挡住，后来的提示「正在应用改动，请稍等」 |

**错误翻译**：维护一张常见错误对照表（缺依赖方案、YAML 语法错、词库找不到、Lua 脚本出错），每种一句白话 + 一条建议。对不上的显示原始日志。

**备份保留**：最近 10 次；第一次接管前那份永久保留。备份只包含配置文件，不含 `build/`、`sync/`、`installation.yaml`、`user.yaml`、`*.userdb` 这些 Rime 自己的运行文件。还原前会先给当前状态做一份「还原前」备份，还原也能撤销。

**隐私**：日志、错误信息只写条数和文件名，不写个人词库、短语、文本替换的内容。

**界面上的做法（阶段 8b 定下）**：
- 改设置（方案、外观、文本替换开关）先改在草稿里，底部出现「有改动还没应用 [撤销] [应用改动]」，点了才走 6.1。草稿不落盘。
- 外部改动：弹窗列出文件，选「覆盖（先备份）」「采用外面改过的个人词库，其余覆盖」（有个人词库被改过时才有）或「放弃这次改动」。
- 下载失败：应用改动时，本地有旧版本就提示，点「先用本地旧版本」再应用一次。第一次打开的引导和导入是一次性的操作，直接用旧版本，结果里提醒。
- 部署有错误或没看到部署完成：提示问题，带「还原到应用改动前」。
- 还原只换回 Rime 目录里的文件，应用里的设置不变，界面上写明；只有文本替换的同步记录会清掉（应用重新读设置，提示重新同步）。
- 文本替换：打开应用时检查一次，同步开着又有变化就问「要现在同步吗」。这个提示和文本替换页的「同步」按钮只同步文本替换，草稿里别的改动留着。

## 8. 测试

### 8.1 宿主机：`swift test`

只碰临时目录，不碰 `~/Library/Rime`、不安装、不切换输入法。

- 打字检查：测试小工具加载 `librime.1.dylib`，在临时配置上模拟打字（方法见 [verified-facts.md](../../verified-facts.md) 第 8 节），例如 `g` → 一、`weixin` → 微信。第二版的试打预览可以复用。
- 测试数据全部自造：不用作者真实的个人词库和文本替换；不把 GPL 文件放进仓库，只做最小的假方案。
- 另有一组联网测试：下载真实上游包检查结构。平时不跑，手动触发。

### 8.2 测试机：`rimectl` 通过 SSH

- **`squirrel-dev`**（长期保留）：应用改动、接管、导出、外部改动冲突。用 `tis-probe`、打字检查确认结果。
- **临时克隆的干净测试机**：从零安装、新电脑一键导入。用户亲手做两步：在窗口里登录桌面、在系统设置里添加输入法。其余由 SSH 完成。

### 8.3 界面

- 逻辑放在 `AppCore`（不含 SwiftUI），在宿主机用假依赖测；视图在 `AppUI`。**不在宿主机上运行应用**（它会读写真实的 `~/Library/Rime`）。
- 打包：不建 Xcode 工程。SwiftPM 的可执行目标 `SquirrelMacOSApp` + `tools/app/build-app.sh` 拼成 `.app`（RimeKit 的资源包放在 `Contents/Resources`），开发期间临时签名；用 `tools/vm/install-app.sh <测试机>` 放进测试机打开（阶段 8a 定下）。发布用 `tools/release/build-release.sh`：release 编译、Developer ID 签名（hardened runtime）、公证、钉票据。
- 每个阶段结束时，在 `squirrel-dev` 里运行真实应用，按检查清单由用户过一遍。
- 主窗口（阶段 8b）：左边栏 6 页（方案、外观、文本替换、导入导出、备份、诊断）；逻辑在 AppCore 的 MainModel，宿主机用假依赖测。
