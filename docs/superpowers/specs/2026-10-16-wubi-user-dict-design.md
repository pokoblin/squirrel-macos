## 1. 目标

用极点五笔的人，常常遇到默认词库里没有的词（人名、公司名、专业术语），只能一个字一个字打。这个功能让用户在应用里把这些词加进个人词库，以后按五笔组词规则打四码就能直接出来。

两种用法（用户说的）：

- **平时偶尔加一两个**：输入一个词，马上看到自动算出的五笔编码，可以手动改，然后加进去。
- **一次批量导入几十上百个**：从文本导入，导入前先列出来检查。

### 用户定下的几件事

| 问题 | 决定 |
|---|---|
| 做哪些输入法 | **只做五笔**（极点五笔 86）。拼音（雾凇、双拼）以后再说 |
| 手动短语（`custom_phrase`）的编辑 | **这次不做**。用户主要用 macOS 自带的文本替换（应用已经能同步） |
| 新词和已有字词编码相同时排第几 | **让用户自己选**。批量导入时默认排在已有字词后面（这一点是设计者定的，用户可以在导入列表里逐个改） |
| 批量导入的格式 | 用户没有现成的格式，交给设计者调研和决定（见 4.3） |

### 不做的事

- 拼音词库、手动短语的编辑。
- 搜狗、QQ 等二进制词库格式（`.scel`、`.qpyd`）。
- 编辑上游的主词库 `wubi86_jidian.dict.yaml`、扩展词库，以及给 iOS 仓输入法用的 `wubi86_jidian_user_hamster.dict.yaml`。只编辑 `wubi86_jidian_user.dict.yaml`。
- 根据用户的输入习惯（`*.userdb`）调整位置：用户选的位置按词库权重算，平时打字时 Rime 自己的调频照旧。
- 上游词库更新后保持「用户想排第 n 个」：只存权重，不另存意图。上游改了相邻字词的权重时，位置可能变，靠 4.6 的检查发现（设计者的决定）。
- 「这个编码现在出什么」不算手动短语和文本替换（它们由短语翻译器排在最前，读文本替换内容还涉及隐私）。某个短语的编码正好和五笔编码相同时，实际位置会往后挪，检查会如实显示（设计者的决定）。

### 失败的样子（即使功能「能用」也算做砸了）

- 加完词，用户以为能打出来，其实打不出来，或者位置和选的不一样。
- 编辑把用户原来手写的个人词库弄乱：丢了注释、分组行、已有的词。
- 新词把常用字从首选位置挤下去，而用户没有选过这样做。

## 2. 已经实测的事实（宿主机配置副本，librime 1.16，2026-10-16）

1. **极点五笔的组词规则写在主词库里**（`wubi86_jidian.dict.yaml` 的 `encoder`）：
   - 二字词 `AaAbBaBb`：第一字前两码 + 第二字前两码；
   - 三字词 `AaBaCaCb`：第一字首码 + 第二字首码 + 第三字前两码；
   - 四到十字词 `AaBaCaZa`：第一、二、三字首码 + 最后一字首码；
   - `exclude_patterns: ['^z.*$']`：`z` 开头的编码不参与组词。
2. **每个字的全码**取主词库里这个字最长的编码（比如「张」有 `xt`、`xta`、`xtay`，全码是 `xtay`；「丰」最长是 `dhk`）。21587 个单字里有 **468 个**（多是生僻字）最长编码不止一个，这时要让用户挑。没有 `z` 开头的单字编码。
3. **只写词、不写编码时，Rime 编译会按上面的规则自己算**：「张三丰」编成 `xddh`，和按规则算的一样。
4. **权重决定同一编码下的顺序**：主词库 `sort: by_weight`；个人词库通过 `import_tables` 并进主词库后，权重照样起作用。实测编码 `wqiy` 原有「你 20、仰泳 10」，加进权重 100、15 和不写权重的三个词以后，顺序是「权重 100 的词 | 你 | 权重 15 的词 | 仰泳 | 不写权重的词」。**不写权重 = 排在最后**。
5. **混输和纯五笔里，同一编码下五笔词库的字词顺序一样，而且排在最前面**：编码 `xddh` 在 `wubi86_jidian` 里是「红艳艳 | 张三丰」，在 `wubi86_jidian_pinyin`（混输，起步方案的默认方案）里是「红艳艳 | 张三丰 | 先打电话 | 现代都会 | …」，拼音和补全出来的候选都排在后面。所以「排第几」指的是五笔词库候选里的位置，在两种方案里都成立。
6. 上游个人词库 `wubi86_jidian_user.dict.yaml` 的头部是 `sort: original`、`dict_grouped: true`，正文只有一条示例「分组词条 wxyt」。上游主词库的权重多是 10 的倍数（10、20、30、40），相邻的字词之间一般有空档。

这些在实现时要写进 `docs/verified-facts.md`。

## 4. 要做什么

### 4.1 新的「五笔词库」页

侧边栏加一页「五笔词库」（放在「试打」后面）。没启用极点五笔的方案时，页面只显示「先在「方案」页启用极点五笔」。

页面分三块：

1. **加一个词**
   - 输入框：输入词以后，马上显示自动算出的编码（4.2）。
   - 有字算不出编码时（主词库里没有这个字），说明是哪个字，要求手动填编码。
   - 有字的全码不止一个时，列出这个词所有可能的编码让用户挑（默认第一个）。
   - 编码框可以手动改。
   - **这个编码现在出什么**：列出同一编码下已有的字词（按顺序，含已经加过的个人词），用户选新词排在第几（默认排在最后）。
   - 这个词已经在个人词库里（同词同码）→ 提示「已经加过了」；主词库或扩展词库里已经有同词同码 → 提示「词库里已经有了」，不让加。
   - 按「加入」。
2. **个人词库列表**
   - 列出 `wubi86_jidian_user.dict.yaml` 里的所有词：词、编码、在这个编码下排第几。
   - 能搜索（按词或编码）、改编码和位置、删除。
   - 「检查能不能打出来」按钮：见 4.5。
3. **批量导入**：按钮「从文本导入……」，可以粘贴，也可以选一个文本文件（4.3）。

### 4.2 自动算编码

- 规则和单字全码都从**本地缓存的极点五笔包**里的 `wubi86_jidian.dict.yaml` 读（`encoder/rules`、`encoder/exclude_patterns`、单字条目），不写死在代码里。
- 单字全码：这个字最长的编码，`exclude_patterns` 匹配的不算。最长的不止一个时，词的可能编码按组合列出来。
- 词的长度按字数算（一个汉字算一个字，包括扩展区汉字）。词里有非汉字（字母、数字、标点、emoji）或主词库里没有的字 → 算不出，要求手动填。
- 只有一个字的「词」也允许加（单字的编码由用户填，自动算不了），这是设计者的决定。
- 手动填的编码：只能是 `a`–`y` 的小写字母，1 到 4 个（`z` 是极点五笔的万能键，不能用在编码里；码长上限 4 来自方案的 `max_code_length`，实现时从编译后的方案文件里确认）。

### 4.3 批量导入的格式（设计者定的）

纯文本，UTF-8，每行一个词：

```
词
词<Tab 或空格>编码
词<Tab>编码<Tab>权重
```

- 只写词：自动算编码，排在已有字词后面（不写权重）。
- 写了编码：用这个编码（不合法就标出来）。
- 写了权重：用这个权重。所以 Rime 的 `.dict.yaml` 正文（`---`…`...` 之间的头部会被跳过）也能直接导入。
- 空行、`#` 开头的行跳过。
- 一行里词和编码之间用 Tab 或空格分开；词本身含空格的，只能用 Tab 分开。

导入前列出所有行，每行显示：词、编码、状态。状态有：

| 状态 | 处理 |
|---|---|
| 可以加 | 默认勾上 |
| 有字算不出编码 / 编码不合法 | 不勾，可以在列表里手动填编码后勾上 |
| 有多个可能的编码 | 默认第一个，可以改 |
| 已经加过了 / 词库里已经有了 | 不勾 |
| 和这次导入里的另一行重复 | 只留第一行 |

用户在列表里可以改编码、改位置、勾选，确认后一起加进去。

### 4.4 存储和生效

- 编辑的是 `personal/dicts/wubi86_jidian_user.dict.yaml`。还没有这个文件时，第一次加词前先定起点：Rime 目录里那份和上游包一样（或不存在）→ 从本地缓存的上游包复制；和上游不一样（用户在应用外手改过）→ 用 Rime 目录里那份。保留原来的头部和条目。
- **不丢词**（设计者的决定，对应「失败的样子」）：打开页面时，如果 Rime 目录里的个人词库在应用外被改过（和账本里记的不一样），页面顶部提示「鼠须管目录里的五笔个人词库在应用外被改过」，按钮「把外面加的词收进来」：按词条合并——外面那份里有、`personal/` 里没有的词条（同词同码算同一条）加进 `personal/`，外面删掉的不跟着删；之后「应用改动」时这份文件不再算外部改动。用户不收也可以继续编辑，但「应用改动」时会按现有的外部改动流程问（选「采用」会用外面那份整份替换，弹窗要说明会丢掉应用里新加的词）。
- **保存时只改词条行**：头部（`---` 到 `...`）、注释行、空行、不认识的行都原样保留，原来的词条顺序不变，新词加在末尾（`sort: original` 下文件顺序不影响位置，位置由权重决定，见 2.4）。
- 每次「加入」、改、删、导入确认都**马上写进 `personal/`**（正本），然后像改了设置一样，底部出现「有改动还没应用」，用户点「应用改动」才写进 Rime 目录、让鼠须管部署。这是设计者的决定，理由：「应用后的样子」试打和 4.5 的检查读的就是 `personal/`，加完马上就能检查。
- 底部「撤销」只撤销设置的草稿，**不撤销**词库的编辑（词库在页面上可以删）。底部的提示要说清楚有词库改动。
- 「应用改动」的其余流程（备份、外部改动检查、编译、部署）不变。

### 4.5 位置和权重

- 「这个编码现在出什么」：解析主词库及它 `import_tables` 里的词库（个人词库用 `personal/` 里的版本，其他用本地缓存的上游包），得到这个编码下的所有词和权重，按权重从大到小排（权重相同时按 Rime 的规则，实现时实测确认）。
- 用户选「排在第 n 个」：算一个权重，放在第 n−1 个和第 n 个之间；选「最后」就不写权重。
- 两个相邻字词之间没有整数空档时（比如权重 20 和 19），**不改别的词的权重**，告诉用户「这个位置放不进去」，让他选别的位置。这是设计者的决定，理由：改上游词或用户已有词的权重会产生意外的连带变化。
- 权重和相同编码的顺序最终以 4.6 的检查为准。

### 4.6 检查能不能打出来

用试打预览的「应用后的样子」：准备副本（编译，极点五笔约几秒到十几秒），然后对要检查的每个词用 `PreviewProbe.find(词, code: 编码)` 找它在第几页第几个，和用户选的位置对比（位置指五笔候选里的位置，见 2.5）。

- 「加入」以后不自动检查（编译要时间）；列表上方的「检查能不能打出来」检查列表里的所有词，批量导入确认后也提示可以检查。
- 结果显示在列表里：「第 1 页第 2 个」（和选的一致）/「位置和选的不一样：第 1 页第 3 个」/「打不出来」。
- 检查用的方案是 `schema_list` 里第一个启用的极点五笔方案（起步方案是混输 `wubi86_jidian_pinyin`），也就是用户平时打字用的那个（简入繁出方案会把简体词转成繁体，只在没有别的极点方案时才用）；没有启用任何极点方案时页面本来就不可用。

### 4.7 `rimectl wubi`

```
rimectl wubi encode <词>...                 打印自动算出的编码（多个可能时都打印）
rimectl wubi list                           列出个人词库里的词
rimectl wubi add <词> [编码] [--position N]   加一个词
rimectl wubi remove <词> [编码]              删除
rimectl wubi import <文件>                   按 4.3 的格式导入（只加「可以加」的行，其余打印出来）
rimectl wubi check                          按 4.6 检查个人词库里所有的词
```

用来测试、在测试机里排查问题。和别的命令一样支持 `--data-dir`、`--rime-dir`。

## 5. 出错和特殊情况

| 情况 | 处理 |
|---|---|
| 没启用极点五笔 | 页面只显示「先在「方案」页启用极点五笔」 |
| 本地没有极点五笔包的缓存 | 「还没下载极点五笔，先应用一次改动」（不在这一页联网） |
| 主词库格式认不出（找不到 `encoder/rules`） | 「认不出这个版本的极点五笔词库，自动编码用不了」，仍可手动填编码 |
| 个人词库文件在应用外被改过 | 和现在一样，「应用改动」时按外部改动处理（可以采用外面的修改） |
| 个人词库文件读不了（不是合法 YAML 头、编码不是 UTF-8） | 页面说明原因，不写任何东西 |
| 检查时编译失败 | 显示翻译过的错误，和「应用」时一样 |

## 6. 隐私

个人词库里可能有人名等个人信息。测试、日志、诊断只统计条数，不打印内容；测试用的词用虚构的。

## 7. 留给实现者的

- 代码分层（RimeKit 里的编码器、词库文件读写、编码索引；AppCore 的页面逻辑；AppUI 的视图），沿用现有的做法。
- 解析大词库（主词库约几十万行）的性能：要在后台做，页面不卡；可以缓存。
- 4.5「权重相同时的顺序」、4.2 码长上限、4.4 合并时「同一条」的判断（同词同码）的实测确认。
- 4.4「外面被改过」的判断沿用账本（ledger）里记的哈希。
- 测试方法：单元测试用夹具词库；集成测试用宿主机鼠须管在临时目录里编译、用辅助程序检查（和试打预览一样）；测试机里检查界面。
