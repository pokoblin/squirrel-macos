# 需求草案

状态：**已和用户逐条确认（2026-10-15）。** 以「已确认的决定」和「第一版范围（已确认）」两节为准；功能需求里和它们冲突的（例如 F7 Profile）以确认结果为准。正式设计见 [第一版设计](superpowers/specs/2026-10-15-squirrel-macos-v1-design.md)。

## 背景和变化

上一个项目 squirrel-wubi86 只为我自己的“极点五笔 + 拼音混输”做配置，所有步骤都在终端里手动完成，记录在它的 README 里。

新项目 squirrel-macos 的目标变了：
- **从“只为我自己适配”变成“支持多种输入方案”**：拼音、五笔、双拼等，全部在界面上操作。
- 引入 **Profile**：把一整套搭配（方案 + 词库 + 外观 + 按键 + 个人词 + 短语）存成一个整体，可以切换、导入、导出。
  - 例：像我这样的五笔用户，可以建一个「五笔」Profile，把极点五笔、拼音混输、雾凇拼音词库整合在一起。样板见 [reference-wubi-profile.md](reference-wubi-profile.md)。

## 目标用户

- 想在 Mac 上用 Rime（鼠须管），但不想碰终端和 YAML 文件的人。
- 有固定习惯的老用户（五笔、双拼），想把自己的一套配置带到新电脑上。

## 功能需求

### F1 安装和环境检查
- 检测：鼠须管装了没有、版本多少；输入法有没有在系统设置里添加；当前有没有选中；上次部署成不成功。
- 一键安装鼠须管：从官方 GitHub 下载 pkg → 校验签名和公证 → 弹系统授权框安装（用户输一次管理员密码）。
- 引导用户在系统设置里添加输入法：一键打开设置页 + 图文说明 + **自动检测添加好了没有**，好了自动切换过去。
- **不要求用户注销**（已实测不需要）。
- 不依赖 Homebrew、python3、git。

### F2 方案目录（选择输入方案）
- 按类别列出可用方案，每个方案说明来源、许可证、大小：
  - 拼音：雾凇拼音（全拼）、明月拼音（鼠须管自带）、袖珍简化字拼音……
  - 双拼：雾凇的 7 种双拼（自然码、小鹤、微软、搜狗、紫光、智能ABC、拼音加加）、官方双拼……
  - 五笔：极点五笔 86（含拼音混输、简入繁出）、官方五笔 86……
  - 其它：仓颉、注音、笔画（鼠须管自带）
- 一键下载、安装、更新、卸载方案。
- 选择启用哪些方案、顺序、默认方案。
- 自动处理方案之间的依赖（例如五笔的拼音反查要用拼音词库）。

### F3 词库
- 给方案挂词库（例如把五笔混输里的拼音词库换成雾凇大词库）。
- 个人词库编辑器：加词时实时显示自动生成的编码（五笔码、拼音），也可以手动改编码。
- 词库更新（例如雾凇词库有新版本时提示）。

### F4 外观
- 候选字、序号、注释的字号（只用真正生效的键名）；浅色和深色两套一起改。
- 配色方案、横排/竖排、每页候选数量。
- 改完能立刻预览。

### F5 按键
- 翻页键（`-` `=`、`[` `]`、Tab）、方案切换快捷键、Shift 中英切换行为等，用开关和下拉框设置。

### F6 自定义短语和 macOS 文本替换
- 手动维护短语列表。
- 从 macOS「文本替换」导入（读系统数据库，只读）；有变化时提示同步。
- 个人隐私：短语内容不上传、不进日志。

### F7 Profile
- 新建、复制、重命名、删除、切换 Profile。
- 一个 Profile 包含：启用的方案和顺序、默认方案、词库搭配、外观、按键、个人词库、自定义短语设置。
- **导出**成一个文件，**导入**后在另一台电脑上还原。导出时可以选择包不包含个人内容（个人词、短语）。
- 能把“已有的 `~/Library/Rime` 配置”导入成一个 Profile（照顾老用户）。
- 内置几个起步 Profile 模板（例如：雾凇全拼、小鹤双拼、五笔 + 拼音混输）。

### F8 应用配置、部署和出错恢复
- 应用任何改动前，先自动备份当前配置；部署失败可以一键还原。
- 先在副本上编译校验，通过了再应用到真实配置。
- 显示部署结果，把日志里的错误翻译成看得懂的话。

### F9 试打预览
- 在界面里输入编码，直接看候选结果，不用切换输入法（用鼠须管自带的 librime）。

## 非功能需求

- 全程不需要终端。
- 不依赖 python3、git、Homebrew（新 Mac 上都没有或是空壳）。
- **绝不把用户配置弄坏**：先备份、先校验、可还原。
- 不改上游方案的原文件，改动都通过 `.custom.yaml` 补丁或应用自己生成的文件完成，这样上游方案更新时不会丢设置。
- 隐私：个人词库、文本替换内容只在本机处理。
- 界面语言：简体中文（是否要多语言待确认）。

## 已确认的决定（2026-10-15）

| # | 问题 | 决定 |
|---|---|---|
| 1 | 给谁用 | **公开发布**。现在只有我自己用，以后开放给别人 → 要走 Developer ID 签名 + 公证，许可证要考虑 GPL 方案 |
| 2 | 技术路线 | **SwiftUI 原生** |
| 3 | Profile | **放弃 Profile 概念**。一台电脑只有一套配置；重点是在应用里方便地导入、导出，并且尽量一键自动完成。F7 改成「导入导出」，下面的 F7 原文作废 |
| 4 | 导出内容 | **只放清单 + 个人内容**，不打包第三方方案；导入时从上游拿最新版 |
| 5 | 方案目录 | **第一版用内置清单**：一个独立的 JSON 文件打包进应用，不写死在代码里；格式照在线清单设计，以后可以加「先拉在线版，失败用内置」 |
| 3b | 应用和已有 `~/Library/Rime` 的关系 | **只管自己生成的文件，外部改动先问**：第一次打开先完整备份，尽量把现有配置认成应用设置（第一版只认清单里的方案），认不出的文件原样保留并列出来；应用记录自己生成的文件和哈希，发现被外部改过就列出来让用户选覆盖还是放弃，覆盖前先备份 |
| 3c | 导出时带不带输入习惯数据（`*.userdb`） | **可以选，默认带上**。用鼠须管自带的 `rime_dict_manager` 导出成文本快照，导入时合并进去，不覆盖新电脑上已经学到的内容 |
| 6 | 高级模式（直接改 YAML） | **暂时不做** |
| 7 | 最低 macOS 版本 | **可以是 macOS 27**，以体验为先 |
| 8 | Windows | **不考虑** |
| 9 | 多台电脑同步 | 可以考虑，**优先级低** |
| — | 第一版范围 | **已确认**，见下面「第一版范围（已确认）」 |
| — | 开发、调试、测试环境 | **继续用 Tart 测试虚拟机**（`tools/vm/`，从 `macos-base` 克隆）。宿主机用 Xcode 编译；应用的运行、调试、测试都在测试机里；只碰临时目录的纯逻辑单元测试可以在宿主机跑。**长期留一台 `squirrel-dev`** 做日常开发（只需登录一次桌面），测「从零安装」「导入导出」这类流程时再临时克隆干净的，测完删 |

## 第一版范围（已确认，2026-10-15）

1. F1 安装和环境检查
2. F2 方案目录：雾凇全拼、雾凇小鹤双拼、极点五笔 86（含拼音混输）
3. F4 外观：字号、配色、横排竖排、每页候选数（浅色和深色一起改）
4. 一键导入导出（替代 F7）：导出方案清单、外观、个人词库、自定义短语、输入习惯；导入时自动装鼠须管、下载最新方案、还原、部署。用户只需输一次管理员密码、在系统设置里添加一次输入法
5. 接管已有配置（见 3b）
6. F6 macOS 文本替换导入（**要先验证**：独立 .app 读 `TextReplacements.db` 会不会被隐私权限拦住）
7. F8 备份、校验、部署、还原

第二版：F3 个人词库编辑器、F5 按键、F9 试打预览、iCloud 同步、在线清单。

## 待确认问题（原始列表，答案见上表）

1. **给谁用？** 只给自己和朋友，还是公开发布？这决定了要不要苹果开发者账号（签名、公证）、许可证怎么选（雾凇、官方双拼是 GPL-3.0）、要不要上 App Store（沙盒大概率做不了这些事）。
2. **技术路线**：SwiftUI 原生（推荐），还是用网页技术（Tauri）做界面？
3. **Profile 和 `~/Library/Rime` 的关系**：Rime 同一时间只有一个用户目录，切换 Profile 就是重新生成这个目录。那么：
   - 输入习惯数据（`*.userdb`，记录你常用哪些字词）要不要跟着 Profile 走？
   - 用户在应用外手动改了 `~/Library/Rime`，应用怎么处理（覆盖、提示、合并）？
4. **导出文件里放什么？** 只放“清单 + 个人内容”，导入时再联网下载方案（文件小、许可证干净）；还是把方案文件也打包进去（离线可用，文件大）？
5. **方案目录怎么维护？** 写死在应用里，还是放一个在线清单可以随时加新方案？
6. 是否需要支持“高级模式”：直接编辑 YAML？
7. 最低支持哪个 macOS 版本？
8. 以后要不要支持 Windows（小狼毫）？这会影响技术路线。
9. 要不要多台电脑同步（iCloud 云盘）？还是只靠导入导出？
