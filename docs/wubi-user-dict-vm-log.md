## 第一部分：联网测试（宿主机）

`RIMEKIT_ONLINE=1 swift test --filter OnlineWubiDictTests`（提交 ee600fe），5 个通过。真的极点五笔包上，「张三丰」`xddh`、「宋氏」`psqa`、「中华人民共和国」`kwwl`、编的五字词 `pqkl`：我们算的编码，和 Rime 自己给没写编码的词算的一致。

测出来的细节都写进了 [verified-facts.md](verified-facts.md) 8.2：

- 权重相同时，没写编码的词排在所有写了编码的词后面。`WubiCodeIndex` 按行序排，对没写编码的词不准（测试里用 `withKnownIssue` 标出）。应用写进去的词都带编码，只影响用户自己手写的没写编码的词。
- 没写编码的词，Rime 会为每种编码组合各建一条，也会用不是最长的编码；编辑器只认第一个最长编码。
- 简入繁出方案下，检查会把简体词报成「打不出来」。已改成检查优先用简体的极点方案（提交 fac22ed，设计 4.6 已补）。
- 短编码（`wq`、`xd`、`qnn`、`ugd`）下，同编码的五笔字词在纯五笔和混输里都排最前。
- 没写编码又编不出码的词：`rime_deployer` 只记一条 E 行（Encode failure），丢掉这个词，退出码还是 0；我们自己的 `DeployerCompiler` 看到 E 行就算编译失败，所以「应用改动」会拒绝。
